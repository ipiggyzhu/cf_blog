# 编程资料库 · 总览

这一卷收的是**编程语言与工程实践**方向的一手来源：语言官方博客、核心开发者的个人站、以及少数几个长期在写实践细节的独立作者。

收录截止 **2026-08-20**，共 **100 条**。

## 这个库怎么用

每条的结构固定：

- **来源** —— 谁写的、发在哪、大概什么时候
- **读它解决什么** —— 你带着什么问题去读，才不算浪费时间
- **要点** —— 从标题与元信息能确认的范围
- **我的补充** —— 我自己在这块踩过的坑、以及和这个博客的实际关系

**要点**里我只写能从标题和元信息确认的东西；**我的补充**是我自己的判断和经验，和原文作者无关。想知道原文究竟怎么讲的，点**阅读原文**。这个库的定位是**导航**，不是原文的替代品。

## 关于来源的选择

**为什么以官方博客为主。** 语言演进这件事，二手转述的衰减特别快。一个特性从 alpha 到 stable 之间语义常常改过好几轮，中文社区的转述文章往往停在某个中间版本上，读者拿着旧语义去写新代码，编译不过还算好运，编译过了但行为不同才麻烦。官方发布公告的好处是它带版本号，你能确认自己读到的是哪一版的说法。

**为什么收了这么多 pythonspeed.com。** 第四卷几乎全是这一个站。Itamar Turner-Trauring 在打包和 Docker 这块写了上百篇，而且是同一个人持续维护、会标注日期和版本、会回头更新的那种写法。这个方向的知识过期极快（`pip` 的行为、基础镜像的选择、PEP 668 之后的破坏性变化），能找到一个持续更新的单一来源，比拼十个来源的碎片更可靠。

**没收进来的。** Real Python 挡了自动抓取（HTTP 403），所以这批里没有它的条目——不是质量问题，纯粹是我这次拿不到它的目录页。想系统学 Python 语法与标准库，它仍然值得单独去逛。另外 Python Insider 官方博客在 2026 年 3 月发过一条"博客已搬迁"的公告，`blog.python.org` 上的新文章可能会逐步停更，后面读到旧链接失效属正常。

## 阅读顺序建议

不建议从头顺着读。按你手上的问题跳：

- **要给 Python 项目做打包或 Docker 镜像** → 直接看第四卷，那一卷是可以照着做的
- **在写 Go 服务、关心并发与 GC** → 第二卷，尤其 GOMAXPROCS 与 GC 那几条
- **想理解 Rust 的编译期检查为什么这么严** → 第三卷，从 borrow checker 那条开始
- **代码能跑但改不动** → 第五卷，那一卷讲的是怎么改而不是怎么写
